# Budget cut-off is an SNS-triggered Lambda that zeroes the ASG

When the monthly gross-spend budget reaches 100%, the alert publishes to an SNS topic and a small Lambda zeroes the worker service's autoscaling target (max 0), the ECS service's desired count, and the ASG (`MinSize`, `MaxSize`, `DesiredCapacity` 0). Amended 2026-11-17: the first version zeroed only the ASG, which cannot stop a running instance. The ASG has scale-in protection and ECS managed termination protection, and with a queue backlog the service keeps wanting its task, so ECS keeps the instance protected and it keeps billing. Zeroing the service first makes the task release its message and lifts the protection. We rejected AWS Budgets actions: an IAM policy does not stop the ASG's service-linked role from launching instances, and SCPs need AWS Organizations, which would upgrade the account and expire the $100 credit for good.

## Consequences

- It is a brake, not a hard cap: Budgets data lags by hours. A running job is aborted and released (SIGTERM), not finished.
- moto does not model scale-in or termination protection, so unit tests only pin the three calls; phase 7 must show the instance actually terminates after a cut-off.
- Terraform also ignores `max_capacity` on the service's autoscaling target, for the same reason as `max_size` below. Restoring after a cut-off takes both commands: `aws application-autoscaling register-scalable-target --service-namespace ecs --scalable-dimension ecs:service:DesiredCount --resource-id service/aivideogen/aivideogen-worker --min-capacity 0 --max-capacity N` (N is 1 while the owner is the only user, 2 later) and the ASG `--max-size` command. The service's desired count needs no restore: autoscaling sets it.
- Terraform must `ignore_changes` on the ASG `max_size`, or the next `apply` undoes the cut-off. `gpu_max` therefore only sets the ASG's *initial* `max_size` (decided 2026-11-16): raising or restoring the limit later is done by hand (`aws autoscaling update-auto-scaling-group --auto-scaling-group-name aivideogen-gpu --max-size N`, or the console), never by `terraform apply`. Re-enabling after a cut-off means doing that after reviewing the bill. We rejected dropping the ignore, because an unrelated `apply` would then silently re-enable GPUs after a cut-off.
- The budget itself is created by hand in the console with credits excluded, so it still trips while the credit absorbs the bill. The topic, Lambda and role live in `budget.tf`.
